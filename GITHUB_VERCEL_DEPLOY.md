# 🚀 Деплой на GitHub и Vercel

## ✅ Нужно ли загружать на GitHub и Vercel?

**Да, рекомендуется!** Вот почему:

### Преимущества GitHub:
- ✅ Версионный контроль кода
- ✅ Резервная копия проекта
- ✅ Совместная работа (если нужно)
- ✅ История изменений
- ✅ Легкая интеграция с Vercel

### Преимущества Vercel:
- ✅ Бесплатный хостинг для Next.js
- ✅ Автоматический деплой при push в GitHub
- ✅ HTTPS из коробки
- ✅ CDN по всему миру
- ✅ Простое управление переменными окружения

## 📋 Пошаговая инструкция

### Шаг 1: Подготовка к загрузке на GitHub

1. **Убедитесь, что `.env` в `.gitignore`:**
   - Проверьте, что `.gitignore` содержит `.env`
   - Это важно для безопасности!

2. **Создайте `.env.example` (если еще нет):**
   ```env
   BASE_SEPOLIA_RPC_URL=https://sepolia.base.org
   BASE_MAINNET_RPC_URL=https://mainnet.base.org
   PRIVATE_KEY=your_private_key_here
   NEXT_PUBLIC_CONTRACT_ADDRESS=0x0000000000000000000000000000000000000000
   ```

3. **Проверьте, что секретные файлы не попадут в репозиторий:**
   - `.env` - должен быть в `.gitignore` ✅
   - `PRIVATE_KEY` - никогда не коммитьте! ✅

### Шаг 2: Создание репозитория на GitHub

1. **Создайте новый репозиторий на GitHub:**
   - Перейдите на https://github.com/new
   - Название: `monstrohunt` (или другое)
   - Описание: "Onchain monster hunting game on Base Network"
   - Выберите **Private** (если не хотите публичный код)
   - НЕ добавляйте README, .gitignore или лицензию (уже есть)

2. **Инициализируйте git и загрузите код:**
   ```bash
   git init
   git add .
   git commit -m "Initial commit: MONSTROHUNT v1.3"
   git branch -M main
   git remote add origin https://github.com/YOUR_USERNAME/monstrohunt.git
   git push -u origin main
   ```

### Шаг 3: Деплой на Vercel

1. **Зарегистрируйтесь на Vercel:**
   - Перейдите на https://vercel.com
   - Войдите через GitHub аккаунт

2. **Импортируйте проект:**
   - Нажмите "Add New Project"
   - Выберите ваш репозиторий `monstrohunt`
   - Vercel автоматически определит Next.js

3. **Настройте переменные окружения:**
   
   В разделе "Environment Variables" добавьте:
   ```
   NEXT_PUBLIC_CONTRACT_ADDRESS=0x...ваш_адрес_контракта...
   ```
   
   ⚠️ **ВАЖНО:** 
   - НЕ добавляйте `PRIVATE_KEY` в Vercel (он нужен только для деплоя контракта)
   - `PRIVATE_KEY` используется только локально для деплоя контракта через Hardhat

4. **Настройте Build Settings:**
   - Framework Preset: **Next.js** (автоматически)
   - Build Command: `npm run build` (по умолчанию)
   - Output Directory: `.next` (по умолчанию)
   - Install Command: `npm install` (по умолчанию)

5. **Деплой:**
   - Нажмите "Deploy"
   - Vercel автоматически соберет и задеплоит проект
   - После деплоя вы получите URL вида: `https://monstrohunt.vercel.app`

### Шаг 4: Настройка автоматического деплоя

После первого деплоя:
- ✅ Каждый push в `main` ветку автоматически задеплоит новую версию
- ✅ Pull requests создадут preview деплои
- ✅ Вы получите уведомления о статусе деплоя

## 🔐 Безопасность

### Что НИКОГДА не должно попасть в GitHub:
- ❌ `.env` файл
- ❌ `PRIVATE_KEY` (приватный ключ кошелька)
- ❌ `node_modules/`
- ❌ `.next/` (build артефакты)

### Что можно безопасно загружать:
- ✅ Весь исходный код
- ✅ `package.json` и `package-lock.json`
- ✅ Конфигурационные файлы
- ✅ `.env.example` (без реальных значений)

## 📝 Чеклист перед загрузкой на GitHub

- [ ] `.env` добавлен в `.gitignore`
- [ ] `PRIVATE_KEY` нигде не закоммичен
- [ ] `.env.example` создан (опционально)
- [ ] Код протестирован локально
- [ ] README.md обновлен
- [ ] Все зависимости в `package.json`

## 🎯 После деплоя на Vercel

1. **Обновите адрес контракта:**
   - После деплоя контракта на Base Sepolia/Mainnet
   - Обновите `NEXT_PUBLIC_CONTRACT_ADDRESS` в Vercel Environment Variables
   - Перезапустите деплой (или сделайте новый commit)

2. **Проверьте работу:**
   - Откройте ваш Vercel URL
   - Подключите кошелек
   - Протестируйте все функции

3. **Настройте кастомный домен (опционально):**
   - В настройках Vercel проекта
   - Добавьте свой домен
   - Настройте DNS записи

## 🆘 Проблемы и решения

### Ошибка при деплое на Vercel
- Проверьте логи сборки в Vercel Dashboard
- Убедитесь, что все зависимости указаны в `package.json`
- Проверьте, что переменные окружения настроены правильно

### Контракт не работает на Vercel
- Убедитесь, что `NEXT_PUBLIC_CONTRACT_ADDRESS` указан в Environment Variables
- Проверьте, что адрес контракта правильный
- Убедитесь, что контракт задеплоен на правильную сеть

### Build fails на Vercel
- Проверьте, что `npm run build` работает локально
- Убедитесь, что все импорты правильные
- Проверьте версии Node.js (Vercel использует последнюю LTS)

## 💡 Рекомендации

1. **Используйте GitHub для версионного контроля** - это стандартная практика
2. **Vercel идеально подходит для Next.js** - бесплатно и автоматически
3. **Храните секреты в Vercel Environment Variables** - безопасно и удобно
4. **Тестируйте локально перед push** - экономит время
