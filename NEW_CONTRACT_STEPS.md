# Пошагово: новый контракт с выводом комиссий

Подробная инструкция: деплой нового контракта (с казной для комиссий) → обновление приложения → как выводить комиссии.

---

## Что изменилось в контракте

- В конструктор добавлен **адрес казны** (treasury). Комиссии **5% с убийства** и **1% с продажи** накапливаются в контракте.
- Только этот адрес может вызвать **`withdrawProtocolBalance()`** и забрать накопленную сумму на свой кошелёк.
- Адрес казны по умолчанию в скрипте деплоя: **`0xEb45918A1efC99C84Fa337E36A2F84317a9DE1b8`**.

Старые контракты (уже задеплоенные) так не обновляются — нужен **новый деплой**.

---

## Часть 1. Подготовка к деплою контракта

### 1.1 Открыть проект в терминале

В Cursor или PowerShell:

```bash
cd C:\MonstroHuntTemp
```

(или твой путь к проекту.)

### 1.2 Проверить .env

В корне проекта должен быть файл **`.env`** (скопирован из `.env.example`).

Открой `.env` и убедись:

| Переменная | Что должно быть |
|------------|------------------|
| `PRIVATE_KEY` | Приватный ключ кошелька **без `0x`**, 64 символа. Этот кошелёк будет платить за газ при деплое. |
| `BASE_MAINNET_RPC_URL` | `https://mainnet.base.org` (или свой RPC). |

Опционально:

- **`PROTOCOL_TREASURY`** — если не задана, при деплое будет использован адрес `0xEb45918A1efC99C84Fa337E36A2F84317a9DE1b8`. Чтобы назначить другую казну, добавь, например:  
  `PROTOCOL_TREASURY=0xТвойАдрес`

### 1.3 ETH для газа

На кошельке, чей **приватный ключ** указан в `PRIVATE_KEY`, должен быть **ETH в сети Base** (Base Mainnet). Без этого деплой не пройдёт.

Проверить баланс можно на [basescan.org](https://basescan.org) по адресу этого кошелька.

---

## Часть 2. Деплой нового контракта на Base Mainnet

### 2.1 Скомпилировать контракт

В терминале (в папке проекта):

```bash
npm run compile
```

Ожидаемый вывод в конце:

```
Compiled 1 Solidity file successfully
```

Если есть ошибки — исправь их перед следующим шагом.

### 2.2 Задеплоить контракт

Выполни:

```bash
npm run deploy:mainnet
```

Подожди 20–60 секунд. В выводе будет что-то вроде:

```
Deploying contracts with the account: 0x...
Account balance: ...
Network: baseMainnet (8453)
Hunger Duration: 604800 seconds (7 days)
Protocol treasury (fee recipient): 0xEb45918A1efC99C84Fa337E36A2F84317a9DE1b8
MonstroHunt deployed to: 0xНОВЫЙ_АДРЕС_КОНТРАКТА
...
Add this to your .env file:
NEXT_PUBLIC_CONTRACT_ADDRESS=0xНОВЫЙ_АДРЕС_КОНТРАКТА
NEXT_PUBLIC_HUNGER_DAYS=7
```

### 2.3 Сохранить адрес контракта

Скопируй из вывода строку **`NEXT_PUBLIC_CONTRACT_ADDRESS=0x...`** (полный адрес без кавычек).

Он понадобится в шагах 3.2 и 4.2.

---

## Часть 3. Обновить приложение локально

### 3.1 Открыть .env

В корне проекта открой файл **`.env`** в редакторе.

### 3.2 Подставить новый адрес контракта

Найди строку:

```env
NEXT_PUBLIC_CONTRACT_ADDRESS=...
```

Замени значение на **новый** адрес из вывода деплоя (шаг 2.3). Пример:

```env
NEXT_PUBLIC_CONTRACT_ADDRESS=0xАДРЕС_ИЗ_ВЫВОДА_ДЕПЛОЯ
NEXT_PUBLIC_HUNGER_DAYS=7
```

Сохрани файл.

### 3.3 Проверка (по желанию)

Запусти приложение локально:

```bash
npm run dev
```

Открой http://localhost:3000. В браузере будет «Open this app inside Base App» — это нормально. Главное — чтобы не было ошибок в консоли и при открытии в Base App приложение подхватывало новый контракт (после того как обновишь Vercel по части 4).

---

## Часть 4. Обновить приложение на Vercel

Чтобы в проде (в Base App) использовался **новый** контракт, нужно задать его адрес в Vercel и задеплоить заново.

### 4.1 Зайти в Vercel

1. Открой в браузере **https://vercel.com** и войди в аккаунт.
2. Выбери проект с Monstro Hunt (тот, что связан с твоим репозиторием).

### 4.2 Изменить переменную окружения

1. Вверху открой вкладку **Settings**.
2. В левом меню выбери **Environment Variables**.
3. Найди переменную **`NEXT_PUBLIC_CONTRACT_ADDRESS`**.
4. Нажми на неё (или на иконку редактирования) и замени значение на **новый адрес контракта** (тот же, что в шаге 3.2). Без пробелов и кавычек, например:  
   `0x1234567890abcdef...`
5. Сохрани (Save).

### 4.3 Запустить новый деплой

1. Перейди во вкладку **Deployments**.
2. У последнего деплоя нажми три точки (**…**) → **Redeploy**.
3. Подтверди. Дождись статуса **Ready** (обычно 1–3 минуты).

После этого приложение по твоему URL (в Base App) будет работать уже с **новым** контрактом. Перепубликовывать приложение в Base App не нужно — меняется только контракт в настройках.

## Часть 5. Как выводить комиссии на кошелёк казны

Комиссии (5% с убийств и 1% с продаж) копятся в контракте. Забрать их может **только** адрес казны: **`0xEb45918A1efC99C84Fa337E36A2F84317a9DE1b8`** (или тот, что ты задал в `PROTOCOL_TREASURY` при деплое).

### 5.1 Убедиться, что есть что выводить

На [basescan.org](https://basescan.org) открой страницу **твоего контракта** (новый адрес из шага 2.3).

- Вкладка **Contract** → **Read Contract**.
- Найди метод **`protocolBalance`** (или поле **protocolBalance**), нажми **Query**. Если значение больше 0 — комиссии накоплены, их можно вывести.

### 5.2 Вызвать вывод через Basescan

1. На странице контракта на Basescan открой вкладку **Contract** → **Write Contract**.
2. Нажми **Connect Wallet** и подключи кошелёк **0xEb45918A1efC99C84Fa337E36A2F84317a9DE1b8** (тот, что указан как казна). Сеть — **Base Mainnet**.
3. В списке методов найди **`withdrawProtocolBalance`**.
4. Поля для ввода нет — метод без аргументов. Нажми **Write**.
5. Подтверди транзакцию в кошельке (оплата газа с адреса казны).
6. После успешной транзакции накопленная сумма в ETH придёт на адрес **0xEb45918A1efC99C84Fa337E36A2F84317a9DE1b8**, а **protocolBalance** в контракте станет 0.

Вызывать **`withdrawProtocolBalance`** можно в любой момент: раз в день, раз в неделю или когда накопится нужная сумма.

### 5.3 Если не находишь withdrawProtocolBalance на BaseScan

**Почему может не быть:** контракт ещё не верифицирован (тогда вкладка «Write Contract» не показывает твои функции) или открыт **старый** адрес контракта (у того контракта такой функции нет).

**Способ 1 — через скрипт в проекте (без BaseScan):**

1. В **`.env`** временно укажи **`PRIVATE_KEY`** от кошелька **казны** (0xEb45918A1efC99C84Fa337E36A2F84317a9DE1b8). В **`NEXT_PUBLIC_CONTRACT_ADDRESS`** должен быть адрес **нового** контракта (с treasury).
2. В терминале из папки проекта выполни:
   ```bash
   npx hardhat run scripts/withdraw.js --network baseMainnet
   ```
3. Скрипт выведет баланс комиссий и отправит транзакцию вывода. Подтверди в кошельке не нужно — подпись идёт через `PRIVATE_KEY`. После выполнения комиссия окажется на адресе казны.
4. После вывода можно вернуть в `.env` прежний `PRIVATE_KEY` (если использовал другой для деплоя).

**Способ 2 — верифицировать контракт на BaseScan:**  
На странице контракта → **Contract** → **Verify and Publish** → укажи компилятор (Solidity 0.8.20), загрузи код `MonstroHunt.sol`, укажи конструктор: `604800,"0xEb45918A1efC99C84Fa337E36A2F84317a9DE1b8"` (для mainnet 7 дней и адрес казны). После верификации появится **Write Contract** и в списке будет **withdrawProtocolBalance**.

## Краткий чеклист

- [ ] В `.env` указаны `PRIVATE_KEY` и `BASE_MAINNET_RPC_URL`, на кошельке есть ETH в Base.
- [ ] Выполнены `npm run compile` и `npm run deploy:mainnet`, адрес контракта скопирован.
- [ ] В локальном `.env` обновлён `NEXT_PUBLIC_CONTRACT_ADDRESS` на новый адрес.
- [ ] В Vercel в Environment Variables обновлён `NEXT_PUBLIC_CONTRACT_ADDRESS`, выполнен Redeploy.
- [ ] Вывод комиссий: с адреса казны вызывается `withdrawProtocolBalance()` на Basescan (Contract → Write Contract).

---

## Важно

- **Старый контракт** (например `0x13406d12...` или `0xe98B...`) остаётся в сети как есть; монстры и балансы на нём не переносятся. Игроки, которые играли по старому адресу, будут видеть своих монстров только если в приложении снова указать старый адрес.
- **Новый контракт** — с нуля: новых монстров нужно создавать заново; комиссии с этого контракта выводятся на казну **0xEb45918A1efC99C84Fa337E36A2F84317a9DE1b8** через **`withdrawProtocolBalance()`**.

Если нужно поменять адрес казны — это можно сделать только при **следующем** деплое нового контракта (задав другой `PROTOCOL_TREASURY` в `.env` перед `npm run deploy:mainnet`).
