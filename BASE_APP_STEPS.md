# Base App: пошагово и подробно

Полная инструкция от «Vercel уже задеплоен» до «приложение опубликовано в Base App». Каждый шаг расписан так, чтобы можно было повторять по тексту.

---

## Что уже должно быть

- Репозиторий на GitHub (например `Jenork/monstrohunt`).
- Проект подключён к Vercel и хотя бы один деплой прошёл успешно.
- Контракт задеплоен на Base Mainnet, адрес в коде/переменных: `0xe98B017b0FF1CEB9e3794883288072Db51382618`.
- В проекте добавлены метатеги для Base (в т.ч. `base:app_id`, `fc:frame`, `fc:miniapp`) в `app/layout.tsx`.

Если чего-то нет — сначала доведи до этого состояния (см. STEP_BY_STEP.md и DEPLOY_TO_BASE.md).

---

## Шаг 1. Переменные окружения в Vercel

**Зачем:** Чтобы приложение знало адрес контракта, сеть и свой публичный URL. Без `NEXT_PUBLIC_URL` метатеги и манифест будут с неправильным доменом.

**Что сделать:**

1. Открой в браузере **https://vercel.com** и войди в аккаунт.
2. Выбери проект с Monstro Hunt (тот, что связан с твоим репозиторием).
3. В верхнем меню проекта нажми **Settings**.
4. В левом сайдбаре выбери **Environment Variables**.
5. Проверь или добавь по одной переменной (для каждой: введи **Key** и **Value**, выбери окружения Production / Preview / Development по желанию, обычно достаточно Production, затем **Save**):

   | Key | Value | Замечание |
   |-----|--------|-----------|
   | `NEXT_PUBLIC_CONTRACT_ADDRESS` | `0xe98B017b0FF1CEB9e3794883288072Db51382618` | Адрес контракта в Base Mainnet. |
   | `NEXT_PUBLIC_HUNGER_DAYS` | `7` | 7 дней до «голода» на mainnet. |
   | `NEXT_PUBLIC_URL` | `https://твой-проект.vercel.app` | **Точный production URL приложения.** Без `https://` в конце слэша. Пример: `https://monstrohunt.vercel.app`. |

6. Если переменные уже были — можно оставить как есть. Если **добавил или изменил** что-то:
   - Перейди во вкладку **Deployments**.
   - У последнего деплоя нажми три точки (**…**) → **Redeploy**.
   - Подтверди. Дождись окончания сборки (обычно 1–2 минуты).

**Проверка:** Открой в браузере `https://твой-проект.vercel.app`. Страница должна открываться; в браузере вне Base App будет сообщение «Open this app inside Base App» — это нормально.

## Шаг 2. Отключить Deployment Protection (для Verify на base.dev)

**Зачем:** Инструмент Base для привязки аккаунта (Verify) обращается к твоему сайту. Если на Vercel включена Vercel Authentication, запрос может не пройти и верификация не завершится.

**Что сделать:**

1. В Vercel остаёшься в проекте → **Settings**.
2. В левом меню найди **Deployment Protection** и нажми.
3. Если пункт **Vercel Authentication** включён (Protected) — переключи в **Disabled** (или сними галочку).
4. Нажми **Save**, если есть такая кнопка.

После получения accountAssociation защиту при желании можно снова включить.

## Шаг 3. Получить accountAssociation (привязка домена к твоему Farcaster-аккаунту)

**Зачем:** Base и Farcaster проверяют, что мини-приложение действительно принадлежит тебе. Для этого нужна подпись с твоего кошелька, привязанного к Farcaster. Результат — три строки: `header`, `payload`, `signature`, которые потом вставляются в манифест.

**Что сделать:**

1. Открой в браузере страницу:  
   **https://www.base.dev/preview**  
   Вверху страницы есть вкладки. Выбери вкладку **Account** (или открой сразу: https://www.base.dev/preview?tab=account).

2. Найди поле **App URL** (или похожее по смыслу). В него нужно ввести **только домен** твоего приложения:
   - Правильно: `monstrohunt.vercel.app` или как у тебя называется проект на Vercel.
   - Неправильно: `https://monstrohunt.vercel.app` или `https://monstrohunt.vercel.app/`.

3. Нажми кнопку **Submit** (или аналогичную). Страница загрузит манифест с твоего сайта.

4. Должна появиться кнопка **Verify**. Нажми её. Откроется процесс подписания:
   - Подключи кошелёк (тот, который привязан к твоему Farcaster-аккаунту).
   - Подтверди подпись в кошельке (MetaMask, Coinbase Wallet и т.п.).
   - Дождись сообщения об успешной верификации.

5. После успешной верификации на странице появится блок с **accountAssociation** — три поля в формате JSON, например:
   - `header` — длинная строка (base64).
   - `payload` — длинная строка (base64).
   - `signature` — длинная строка (обычно начинается с `MH0x` или похоже).

6. Скопируй **значения** этих трёх полей (сами строки в кавычках, без ключей `"header"`, `"payload"`, `"signature"`). Можно скопировать весь JSON и потом вставить в редактор — главное не потерять кавычки и не обрезать строки.

**Если не получается:**
- Убедись, что в App URL нет `https://` и слэша в конце.
- Проверь, что на Vercel отключена Deployment Protection (шаг 2).
- Убедись, что последний деплой на Vercel успешен и сайт открывается по этому домену.
- Проверь, что в манифесте по адресу `https://твой-домен.vercel.app/.well-known/farcaster.json` возвращается JSON (открой эту ссылку в браузере).

## Шаг 4. Вставить accountAssociation в проект

**Зачем:** Манифест по адресу `/.well-known/farcaster.json` отдаётся из кода. В нём должен быть заполненный объект `accountAssociation`, иначе Base не считает приложение привязанным к твоему аккаунту.

**Что сделать:**

1. В редакторе (Cursor/VS Code) открой файл в **корне проекта**: **`minikit.config.ts`**.

2. Найди блок:
   ```ts
   accountAssociation: {
     header: "",
     payload: "",
     signature: ""
   },
   ```

3. Замени пустые строки на скопированные значения из шага 3. Пример (значения у тебя будут свои):
   ```ts
   accountAssociation: {
     header: "eyJmaWQiOjkxNTIsInR5cGUiOiJjdXN0b2R5Iiwia2V5IjoiMHgwMmVmNzkwRGQ3OTkzQTM1ZkQ4NDdDMDUzRURkQUU5NDBEMDU1NTk2In0",
     payload: "eyJkb21haW4iOiJtb25zdHJvaHVudC52ZXJjZWwuYXBwIn0",
     signature: "MHh..."
   },
   ```
   - Вставляй **целиком** каждую строку, не обрезай.
   - Каждое значение должно оставаться в кавычках.
   - После последнего поля (`signature`) стоит запятая перед `miniapp`.

4. Сохрани файл (Ctrl+S / Cmd+S).

**Проверка:** В проекте не должно быть синтаксических ошибок (красные подчёркивания в `minikit.config.ts`). Если используешь `npm run build` — сборка должна проходить без ошибок.

## Шаг 5. Закоммитить изменения и отправить на GitHub

**Зачем:** Vercel собирает проект из репозитория. Чтобы на продакшене появился манифест с accountAssociation, изменения должны быть в ветке `main` и запушены.

**Что сделать:**

1. Открой терминал в папке проекта (например в Cursor: Terminal → New Terminal). Убедись, что находишься в корне репозитория (где лежат `package.json` и `minikit.config.ts`).

2. Посмотри, какие файлы изменены:
   ```bash
   git status
   ```
   Должны быть как минимум `minikit.config.ts`. Могут быть и другие (например `app/layout.tsx`, если ты их правил).

3. Добавь нужные файлы в коммит:
   ```bash
   git add minikit.config.ts
   ```
   Если ещё менял layout или другие файлы для Base App:
   ```bash
   git add app/layout.tsx
   ```
   Или добавить всё изменённое:
   ```bash
   git add -A
   ```
   (осторожно: не должно попасть ничего лишнего, например `.env` — он в `.gitignore`.)

4. Создай коммит:
   ```bash
   git commit -m "Add accountAssociation for Base Mini App"
   ```

5. Отправь изменения на GitHub:
   ```bash
   git push origin main
   ```
   Если попросит логин/пароль — используй свой GitHub-аккаунт или токен.

6. Зайди в Vercel → вкладка **Deployments**. Должен появиться новый деплой (триггер — push в `main`). Дождись статуса **Ready** (обычно 1–3 минуты).

**Проверка:** Открой в браузере:  
`https://твой-проект.vercel.app/.well-known/farcaster.json`  
В ответе должен быть JSON, а в нём объект `accountAssociation` с непустыми `header`, `payload`, `signature`.

## Шаг 6. Проверка в Base Build Preview

**Зачем:** Убедиться, что Base видит манифест, метатеги и привязку аккаунта без ошибок (в том числе что ошибка «Metatag base:app_id not found» исчезла).

**Что сделать:**

1. Открой в браузере: **https://base.dev/preview**.

2. В поле для URL введи полный адрес приложения, например:  
   `https://твой-проект.vercel.app`  
   (тот же, что задан в `NEXT_PUBLIC_URL`). Нажми Enter или кнопку проверки.

3. Посмотри три блока (вкладки/секции):
   - **Launch**  
     Должна быть кнопка запуска приложения. Нажми — откроется твоё приложение (в iframe или в новой вкладке). Убедись, что оно загружается (может быть сообщение «Open in Base App» — это нормально для браузера).
   - **Account association**  
     Должны быть зелёные галочки или статус «Verified» / «Valid». Не должно быть красных ошибок о неверной подписи или домене.
   - **Metadata**  
     Должны отображаться название, описание, иконка, категория, теги из манифеста. Не должно быть сообщений вроде «Metatag base:app_id not found» или «fc:frame missing».

4. Если где-то есть ошибки — вернись к соответствующему шагу (переменные в Vercel, accountAssociation в `minikit.config.ts`, пуш, деплой) и исправь. Затем снова проверь Preview (иногда кэш обновляется не сразу, подожди 1–2 минуты после деплоя).

## Шаг 7. Опубликовать приложение в Base App (пост с ссылкой)

**Зачем:** Чтобы пользователи могли открыть твоё мини-приложение по ссылке в ленте и добавить его в Base App. Без поста с URL приложение не появится в ленте и его сложнее найти.

**Что сделать:**

1. Установи и открой **Base App** (или открой в браузере, если поддерживается):
   - Обычно это приложение Base в телефоне или по ссылке с base.org.

2. Войди в аккаунт (тот же, с которым делал Verify на base.dev).

3. Создай **новый пост** (кнопка «Post», «Compose», «New» — в зависимости от интерфейса).

4. В текст поста вставь **ссылку на твоё приложение** — тот же URL, что в `NEXT_PUBLIC_URL`, например:  
   `https://твой-проект.vercel.app`  
   Некоторые клиенты автоматически превращают ссылку в карточку (превью с кнопкой «Launch»). Если нет — ссылка всё равно будет кликабельной.

5. При желании добавь короткий текст, например: «Monstro Hunt — ончейн-игра на Base. Создавай монстра, корми, охотись за другими. Только ETH.»

6. Опубликуй пост.

7. Открой этот пост (например у себя в профиле или в ленте). Нажми на ссылку — должно открыться твоё мини-приложение внутри Base App с подключённым кошельком.

**Проверка:** Открой ссылку из поста в Base App на телефоне или в браузере. Должен открыться Monstro Hunt, кошелёк подключается автоматически, можно зайти в Create / Manage / Hunt.
